# AIニュース動画 標準ビジュアル仕様

## 1. 正本・コンセプト

本書を `daily_story` 系の日次AIニュース動画の標準ビジュアル仕様とする。シリーズの約束は **「もぞが、難しいAIニュースをやさしく噛み砕いて解説するAIニュース動画」**。1080×1920、9:16、30fps、スマホ最優先、1画面1メッセージとし、ニュース感・テック感・親しみやすさを両立する。

最優先は「短さ」ではなく **ニュースを理解できること**。固定4ページ・固定14〜20秒を完成条件にしない。説明に必要ならページ数と尺を増やし、専門用語や背景を飛ばして意味不明にすることを禁止する。一方で冗長な繰り返しは避ける。

既存の事実・音声・媒体QAは本書より優先して維持し、合格のために閾値を緩めない。

## 2. 解説の主役は「ニュースの意味」

冒頭の問い・見出しは、単なる用語解説ではなく **そのニュースで視聴者が知りたい結論・変化・理由** を表す。

- 悪い例: `30Bって何？` だけで動画の主題を終える
- 良い例: `いま30B級が注目される理由`

専門語の定義は、主題を理解するための途中ページとして必要な分だけ説明する。専門的なテーマでは、必要に応じて「全体像 → 用語 → 位置づけ → 今回起きたこと → なぜ注目されるか → 注意点・影響 → 結論」の順を優先する。

## 3. ページ数・尺は内容に合わせる

- 通常は4〜10ページの範囲から内容に必要なページ数を選ぶ。
- 10ページは異常生成を止める安全枠であり、必要な説明を削る理由にはしない。
- 各ページの表示時間は日本語ナレーション量に応じて可変にする。
- ナレーションを早口にして固定尺へ押し込まない。
- 長い説明は文字を小さくせず、ページを分ける。

## 4. 冒頭3秒は「サムネイルそのもの」

0.000〜3.000秒は通常の説明スライドではなく、YouTube Shorts一覧で静止画として見ても成立する **専用サムネイル構図** とする。

### 共通必須条件

- 0 / 1 / 2 / 2.967秒のどこを静止画化してもニュースのテーマとフックが分かる。
- 見出しは最大2行、1行9文字前後を目安にし、実幅でsafe area内へ収める。
- 見出しは記事タイトルの縮小コピーではなく、結論・驚き・違和感・危機感・明確な利益のいずれかを短く伝える。
- 専門用語だけを大きく置いて終わらない。初心者が意味を取れない語は、ニュースの意味へ言い換える。
- **1つの強い見出し + 1つの主ビジュアル** を基本とする。
- 0〜3秒に `support_text`、全文字幕、長い説明文、もぞの長い吹き出しを表示しない。
- 詳細説明と全文字幕は3秒以降に戻す。
- もぞと `AIツールウォッチ` は小さなブランドアンカーとして扱い、ニュースの主役より目立たせない。

## 5. 冒頭サムネイル A / B / C の自動選択

`thumbnail_style` は **冒頭3秒専用** の契約であり、後述の本編 `visual_template` A/B/Cとは別物とする。

### A — 号外・新聞見出し風

**対象:** 危険、規制、セキュリティ、障害、炎上・論争、緊急性のある問題提起。

**狙い:** 危機感・速報感・緊張感を、誇張せず一瞬で伝える。

**表現:** 太い大見出し、強いコントラスト、オレンジ等の警戒アクセント、実際の対象同士の緊張・衝突が分かる1場面。警告アイコンの大量配置や、元情報にない破壊・恐怖表現は禁止する。

### B — 雑誌表紙・編集特集風

**対象:** 大きな潮流、業界変化、注目テーマ、AIエージェント、モデル規模・位置づけ、市場変化、「なぜ今重要か」の解説。

**狙い:** 知的で重要そうに見え、続きを知りたくなる編集特集感を出す。

**表現:** 大見出し + 1つの編集的ヒーロー画像。図解を詰め込まず、主役・製品・出来事を大きく扱う。

### C — シンプル断言ポスター風

**対象:** 新機能、性能向上、記憶・コンテキスト、速度、音声、UIなど、一言でユーザー価値が伝わる変化。

**狙い:** 一瞬で「何が良くなる／変わる」が分かることを最優先にする。

**表現:** 3方式の中で最も短く大きい見出し、1つの対象・動作・Before/After。余白を多くし、装飾物を増やさない。

### 選択の優先順位

- 警戒・規制・問題提起・緊急性 → **A**
- トレンド・潮流・業界解説・位置づけ → **B**
- 機能進化・性能・分かりやすい利用者メリット → **C**
- 迷う場合は、危機感が主題ならA、業界全体の意味ならB、利用者に直感的な変化ならCを選ぶ。

A/B/Cの選択は見せ方だけを変え、ニュースの事実・強さ・因果を追加してはならない。

## 6. 冒頭のNG

以下をサムネイルの主役にしない。

- 小さな説明文、長い本文、全文字幕
- `AGENT`、`LONG CONTEXT`、`AI`など抽象語だけの大見出し
- AIチップ + 盾 + ロボット + フローチャート + 矢印を並べた汎用AIアイコンコラージュ
- 何を意味するか分からないネオン図解
- 似たレイアウトを毎日機械的に繰り返すこと
- ニュース内容と無関係な「未来感」の装飾
- 元情報より強い危機・成功・性能の断定

シリーズ統一は **配色・タイポグラフィ・もぞ・ブランド位置** で保ち、ニュースごとの差はA/B/Cと主ビジュアルで出す。

## 7. 字幕・説明文の可読性

スマホで通常の視聴距離から読めることを必須とする。

- 本編字幕は52px前後を標準、48px未満にしない。
- 字幕は最大4行まで許容するが、1行16〜18文字程度を目安に分割する。
- 長い説明を小さな文字で1枚へ詰め込まない。
- 補足文も48px前後を標準とする。
- 高コントラストの背景パネルを使い、背景画像に文字を埋もれさせない。

## 8. 固有の背景言語・生成画像

黒・濃紺・深い青を基調に、ゴールド／オレンジ、紫／ラベンダー、青を少量使う。疎な回路、光点、細線、幾何、緩いグリッド、紙感や粒子は後景として許容する。

特定のShorts、クリエイター、媒体、公式サイトUIを模倣しない。大量の0/1、Matrix rain、ネオン過多、サイバーパンク定型、白いAIロボット、光る脳・球、ストック風企業絵、記事サイトのスクリーンショット、読める偽UIを禁止する。生成画像には文字・数字・ロゴ・透かしを入れない。

生成画像は「AIを描く」のではなく、**そのニュースで実際に何と何の関係が変わるのか** を、人物・製品・対象・場面で示す。1枚1メッセージ、主役は1つに絞る。

## 9. 本編 visual_template（冒頭A/B/Cとは別）

本編の説明ページは従来どおり、内容に応じて次の説明テンプレートを使える。

- **A — 仕組み解説:** 入力・仕組み・変化などの関係を具体的に示す。
- **B — 新機能・新発表:** 発表主体・対象・変更点を示す。
- **C — 比較・位置づけ:** 2カラムやスケールで比較軸を示す。

これらは `visual_template`、冒頭3秒は `thumbnail_style` として明確に分離する。

## 10. もぞの固定アセット仕様

公式見本は `assets/visual-references/mozo/mozo-character-reference.png`。動画では承認済みの背景透過 `assets/visual-references/mozo/mozo-opening.png` を固定合成する。

- ラフな手描き感、シンプルな白い体、左右非対称の輪郭。
- **白目は禁止**。目は濃色の塗りだけで左右の大きさを変える。
- 控えめな表情、茶色の小さなリュック、緑色のやさしい手を維持する。
- 生成画像にもぞや代替マスコットを描かせない。
- 冒頭では小さく扱い、見出しや主ビジュアルと競合させない。

## 11. 本編の文章設計

- 1ページ1メッセージ。
- 見出しは「何の話か」「何を理解するページか」が一目で分かる具体語を使う。
- `30B`、`パラメータ`、`推論`、`コンテキスト`など初心者が知らない可能性が高い語は必要に応じて平易に定義する。
- 定義自体を動画の主題にしない。
- 「誰が・何を・なぜ」が分かる文章を優先する。
- 例えは元情報にない性能断定や誤解を生まない範囲で使う。

## 12. QA・公開ゲート

story validation、voice QA、headline semantic match、opening QA、完全decode、black frame、MP4生成、1080×1920、音声、25MiB以下、`auto_publish_ready` を維持する。

追加で次を確認する。

- `thumbnail_style` がA/B/Cのいずれかで、ニュースの性質に合っている。
- 冒頭見出しは最大2行で、スマホ縮小表示でも即読できる。
- 0〜3秒に小さな説明文・全文字幕が出ていない。
- 主ビジュアルが1つに絞られ、ニュースの意味を補強している。
- 汎用AIアイコンの寄せ集めになっていない。
- 3秒以降には必要な本編字幕・説明が復帰している。
- A/B/Cを使い分けても、AIツールウォッチのシリーズとして見える。
- 機械QA後も0 / 1 / 2 / 2.967秒の代表フレームをスマホ相当サイズで目視する。

## 13. 完成基準

完成とは「整っている」だけではなく、**一覧で見たときに一瞬で読め、何のニュースか分かり、続きを見たくなること**。

説明スライドをそのまま冒頭に置くのではなく、冒頭3秒は広告ポスター／編集表紙のように情報を削り、本編は3秒以降で丁寧に解説する。この二段構成を標準とする。
