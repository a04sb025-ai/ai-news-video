# OpenMontage用 AIニュース動画 冒頭3秒・ビジュアル仕様

## 目的
AIニュース動画において、最初の数秒でスクロールを止めてもらい、スマホ視聴でも一瞬で内容が伝わる状態を完成基準とする。

特に **冒頭3秒は「サムネイルそのもの」として成立すること**、および **目を引く主要ビジュアルを用いてニュースの主題を直感的に伝えること** を必須要件とする。

## 1. 基本仕様
- 形式：縦型動画
- 解像度：1080 × 1920
- アスペクト比：9:16
- フレームレート：30fps
- 尺：10〜15秒
- 言語：日本語
- 原則：1動画1ニュース

## 2. 編集方針
- 一次情報を優先する
- 誇張表現を禁止する
- 推測を含む場合は推測と分かるように明示する
- 冒頭3秒以内にフックを入れる
- 音声なしでも冒頭の内容が理解できる構成にする
- 標準構成は **タイトル（0〜3秒）→「つまり、何？」（3〜6秒）→「ここが新しい／ここがポイント」（6〜9秒）→追加の重要ポイント（9〜12秒）→アウトロ（12〜14秒）** とする
- 各画面は1メッセージに絞り、ニュース本編よりアウトロを目立たせない

## 3. 冒頭3秒の完成基準
冒頭3秒は、**静止画として切り出してもそのままサムネイルとして成立する品質**でなければならない。

### 必須条件
- 最初の3秒だけを見ても、ニュースのテーマ・要点・インパクトが一瞬で伝わること
- 音声なしでも、何のニュースか大まかに理解できること
- スマホでスクロール中でも読める大きな見出しであること
- 1画面1メッセージを原則とすること
- 文字と背景に十分なコントラストがあること
- 数字・結論・疑問形など、強いフック要素を優先すること
- 画面内で最も大きい要素は、ニュースの主役またはニュースの結論であること
- 意味の弱い星、抽象アイコン、単なる「AI」吹き出しを冒頭の主役にしないこと
- 人物＋短い強い結論を基本に、縦長フィードの静止状態でも即読できること

## 4. 目を引く画像（主要ビジュアル）仕様
冒頭3秒には、**視聴者の目を止めるための主要ビジュアル（hero image）を必ず配置する**。

### 目的
- スクロールを止める
- ニュース内容をひと目で伝える
- 見出しの理解を補強する

### 必須条件
- 主要ビジュアルは、ニュースの主題が一目で分かる画像にする
- 主役となる人物・製品・出来事・場面を大きく見せる
- 背景より主題が目立つ構図にする
- 画像は単なる飾りではなく、内容理解を助ける役割を持たせる
- 文字を重ねても可読性が保てる視認性を確保する
- ニュース内容と無関係な汎用イメージは避ける
- 一次情報にない印象操作や誇張を誘発する画像演出は避ける

### 推奨事項
- 人物の顔、製品の形、象徴的な場面など、認識しやすい要素を優先する
- 画面内で視線が集中する位置に主題を置く
- 背景が複雑すぎる場合は、トリミング・ぼかし・明暗差で主題を際立たせる

## 5. テキスト表示仕様
- 字幕・テロップは短く区切る
- 1キュー最大18文字を目安とする
- 最大2行までとする
- セーフマージン内に配置する
- 冒頭見出しは通常字幕よりも大きく、最優先で読めること

### 冒頭見出しの原則
- 文章を長くしすぎない
- 1つの主張だけを強く見せる
- 数字、結論、疑問形を優先して使う
- 途中で終わる表現を避け、「何が起きたのか」が一瞬で分かる文にする

## 6. 冒頭フレームQA仕様
冒頭の訴求力を担保するため、**0.5秒・1.5秒・2.5秒のフレームを切り出して確認する**。

### QAチェック項目
- 音なしでも何のニュースか分かるか
- 最重要メッセージが一瞬で読めるか
- 画像が目を引き、内容理解を助けているか
- スマホ表示で文字と画像が埋もれていないか
- 続きを見たくなるインパクトがあるか
- 主要ビジュアルがニュースの主題と一致しているか
- 不要な空白が多すぎず、字幕やUIが人物の顔・重要要素を隠していないか

### 再修正条件
上記のいずれかが弱い場合は、以下を修正して再レンダリングする。
- 見出し文言
- 文字サイズ
- レイアウト
- 背景とのコントラスト
- 主要ビジュアル
- 構図
- 画面内の情報量

## 7. 完成動画の最終確認
完成後は、通常の映像QAに加えて以下を確認する。
- 字幕と音声の同期
- 誤字脱字
- 異常フレームの有無
- 黒画面・静止フレームの有無
- ラウドネス
- 冒頭3秒がサムネイル品質として成立しているか
- 冒頭の画像が十分に目を引くか
- 冒頭だけでニュースの主題が伝わるか

## 8. 自動修正ルール
完成チェックで問題を検出した場合は、自動で修正し再レンダリングする。

### 特に再修正対象とするケース
- 冒頭の見出しが小さく読みにくい
- 文字数が多く瞬時に理解できない
- 画像が弱く、スクロールを止める力が不足している
- 画像が内容理解に寄与していない
- 何のニュースか一瞬で分からない
- インパクトはあるが誇張に寄りすぎている

CIは `scripts/check_opening_frames.py` で0.5 / 1.5 / 2.5秒をPNGへ抽出し、黒画面、空フレーム、コントラスト、見出し構造を検査する。失敗時は人物ヒーロー画像を維持したまま見出し背景をさらに暗く強化し、1回だけ再レンダリングして再検査する。画像生成自体が失敗した場合だけ、決定的なモーショングラフィックスへフォールバックする。機械判定で意味や魅力を断定せず、出力された3枚について上記項目を人間が最終承認する。

## 9. 字幕と生成画像の標準
- 字幕はJSONキーを表示せず、ナレーションと同じ意味の自然な日本語だけを最大2行で出す
- 単語途中の機械的な改行を避け、長文は脚本段階で短文化する
- 画像上の字幕には暗色パネルまたは縁取りを付け、顔を避けた下部セーフ領域へ置く
- 生成画像には文字を含めず、人物の顔を大きく、主役を1つにし、字幕・見出し用の余白をプロンプト段階で指定する
- 生成済み画像はニュース単位の安定したファイル名でキャッシュし、再レンダリングで再課金しない
- Provider障害やSecret未設定時は、意味が保たれるモーショングラフィックスへフォールバックする

## 10. 音声の標準
- 画面で短く読ませる `caption` / `subcaption` と、自然に聞かせる `narration` は分離する
- TTSへ英字略語を直接渡さず、自然な日本語読みに書き換える
- `ChatGPT` は表示では英字を使用してよいが、音声では必ず **「チャットジーピーティー」** とする
- 各シーンの音声を個別生成してシーン尺へ収め、連結後もシーン境界との同期を維持する
- CIで表示文と音声文の分離・必須読みを機械検査し、完成MP4の実再生でも読みと同期を確認する

## 11. イラスト設計ルール：生成AIっぽさを減らす
AIニュース動画のイラストは、**「AIそのもの」を描くのではなく、「AIを使う人の状況」と「ニュースの意味」を描く**ことを基本方針とする。

### 目的
- 生成AI特有の既視感を減らす
- 説明図から、記事のトップ画像のようなエディトリアルな一枚絵へ近づける
- スマホ上で止まりたくなる魅力を持たせる
- ニュース内容を人物中心で直感的に理解させる

### 必須ルール
1. **主役は人**
   - 原則として、ニュースの利用者・登場人物・影響を受ける人を主役にする
   - 人物の顔や表情を大きく見せ、感情や状況が一瞬で伝わる構図にする

2. **AIをロボットで表現しすぎない**
   - 汎用AIロボット、白い人型マスコット、いかにも生成AIらしい擬人化表現は原則避ける
   - AIの存在は、画面UI、会話カード、ガイド表示、入力画面、状況描写で示す

3. **説明図よりエディトリアル寄り**
   - 教材・プレゼン資料・インフォグラフィック風ではなく、記事トップや雑誌挿絵のような一枚絵を目指す
   - ただし意味が分からなくなるほど抽象化しない

4. **人物の個性と自然さ**
   - 顔は大きめ
   - 表情は自然で、発見・驚き・思考・安心などシーンの意味に合った感情を持たせる
   - 完璧すぎる平均顔・無難な優等生イラストを避け、少し個性を持たせる

5. **質感**
   - ツルツル・ピカピカしすぎるCG風を避ける
   - わずかな紙感、粒子、ラフさ、柔らかな塗りなど、人の手を感じる質感を許容する
   - ストックイラスト感を弱める

6. **字幕・見出し余白**
   - 画像生成時点で、見出しや字幕を置く領域を確保する
   - 顔・手・デバイス画面など重要要素に文字が重ならない構図を優先する

7. **画像内テキスト禁止**
   - 生成画像そのものには文字を入れない
   - 文字情報は動画側で重ねる

8. **1枚1メッセージ**
   - 要素を詰め込みすぎず、そのシーンで伝えるべき意味を一つに絞る

### 禁止寄りの表現
- AIロボットを毎回大きく配置する
- AI＝ロボット、AI＝発光する脳、AI＝抽象発光体、のような使い古された記号を主役にする
- 本・盾・時計などのアイコンだけで場面を成立させる
- 教材・ポスター・プレゼン資料のような説明図に寄りすぎる
- 人物が小さく、記号の方が目立つ構図
- シリーズ内で画風が大きくぶれる

### 生成プロンプト共通条件
- human-centered editorial illustration
- expressive, believable human face
- AI shown through interface and context, not a robot mascot
- visually striking, thumbnail-worthy composition
- subtle texture, not overly smooth or stock-like
- no generated text inside the image
- clean negative space for headline/subtitles
- one visual message per scene

## 12. 「ティーン向けChatGPT」シーン別イラスト指示
以下を、このニュースの画像生成における基準プロンプトとする。

### Scene 1：10代は専用ChatGPTへ
**役割:** 冒頭サムネイル。何のニュースかを一瞬で伝える。

**指示:**
10代の学生を主役にしたスマホ向け縦構図のエディトリアルイラスト。学生がノートPCまたはタブレットを見て、少し驚きや発見のある表情をしている。画面にはChatGPTを連想させるシンプルな会話UIやガイドカードが見えるが、ロボットは出さない。主役の顔を大きく、ニュース動画のサムネイルとして目を引く構図にする。背景は整理し、大きな見出しを載せる余白を確保する。高コントラストで、説明図ではなく記事のトップ画像のような魅力的な一枚絵にする。画像内に文字は入れない。

### Scene 2：答えを出すより、考えさせるAIに
**役割:** AIが正解を丸投げせず、考える方向へ導くことを見せる。

**指示:**
10代の学生が机で問題やノートに向き合いながら考えている様子を描く。ノートPCまたはタブレットの画面には、AIが正解を直接出すのではなく、ヒントや問いかけを返しているようなUIを見せる。ただし画像内には文字を生成しない。ロボットは出さず、AIは画面UIと状況で表現する。人物の表情は「困っている」より「考えている」「気づき始めている」印象にする。字幕余白を確保しつつ、人物主体で魅力的に見せる。

### Scene 3：危険な内容への保護を標準で強化
**役割:** 危険そのものではなく、「10代が守られている」ことを見せる。

**指示:**
10代の学生が安心してデバイスを使っている様子を描く、やや落ち着いたエディトリアルイラスト。安全機能は露骨な警告や危険表現ではなく、画面UIの保護レイヤーや構図全体の安心感で表現する。盾アイコンだけの説明図にせず、人物中心で学生の安心感が伝わる一枚絵にする。ロボットは出さない。画像内に文字は入れない。スマホ視聴でも意味が伝わるシンプルで強い構図にする。

### Scene 4：使いすぎや依存も抑える設計
**役割:** AIと適切な距離感を保つ設計を見せる。

**指示:**
10代の学生がAIを使いながらも、適切な距離感で付き合っていることが伝わるエディトリアルイラスト。画面には時間管理や休憩を連想させる穏やかなUI要素があり、学生が一息ついたり少し手を止めたりしているニュアンスを入れる。AIは依存対象ではなく、あくまで支援ツールとして感じられる構図にする。ロボットや擬人化AIは出さず、人物とUI、生活感のある状況で表現する。画像内に文字は入れない。説教くさくならず、自然に「使いすぎを抑える」雰囲気を見せる。

### Scene 5：アウトロ
- 情報量を増やさない
- 主役はブランド文字
- 背景イラストは控えめ
- ニュース本編より目立たせない

## 13. シリーズの画風統一
- ニュースごとに人物や舞台は変えてよいが、エディトリアル寄り・人物主体・適度な質感・高コントラストという共通言語を維持する
- 「AIニュースだから毎回AIロボット」という表現を禁止する
- ニュース固有の主役・場面・利用者を優先して描く
- 同一動画内では人物描写、線・塗り、質感、彩度、光の方向をできるだけ統一する
- サムネイル画像だけ極端に別テイストにしない

## 14. 仕様要約
この仕様で最も重要なのは以下の5点である。

1. **冒頭3秒はサムネイルとして成立すること**
2. **目を引く主要ビジュアルで視聴を止めること**
3. **スマホで一瞬で読める見出しで内容を理解させること**
4. **AIそのものではなく、AIを使う人とニュースの意味を描くこと**
5. **生成AI特有のロボット・教材・ストック風の既視感を避け、人物主体のエディトリアル表現を標準にすること**

以上を、OpenMontageで制作するAIニュース動画の標準ルールとする。
